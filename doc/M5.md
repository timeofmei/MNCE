# M5：Windows 自定义标题栏

> 状态：已完成。Windows 原生边界修订已经实现，并通过 Debug、Release 自动测试及 Windows 11 人工验证。首版纯 Qt 无边框方案不能保留系统贴靠；本次修订增加了严格限界的 Windows 窗口框架适配层。

## 目标

在 Windows 基线环境隐藏主窗口原生标题栏，提供与 MNCE 主界面一致的自定义标题栏，同时保留最小化、最大化、还原、关闭、拖动、系统贴靠和边缘缩放等基础桌面窗口行为。

M5 仍优先依赖 Qt 6.11.2 的公开跨平台接口。为恢复 Windows 11 原生贴靠，仅 Windows 窗口框架适配层可以使用本文明确列出的 Win32 窗口样式和非客户区消息；自定义标题栏组件、通用窗口状态逻辑和业务代码不包含平台原生代码。其他目标平台继续使用原生标题栏，待各平台单独验证后再决定是否启用。

## 已确认决策

- M5 先支持 Windows 11，平台和工具链基线沿用[平台、发行与许可证](platform-and-distribution.md)。
- 实现尽量通用并优先使用 Qt 提供的功能和接口；Windows 专有代码只允许存在于本文定义的窗口框架适配层。
- 自定义标题栏不放目标语言选择器；现有选择器继续位于主窗口内容区左上角，符合[页面与导航](ui-structure.md)的既有规则。
- 不提供标题栏右键菜单。

## 修订依据与决定

首版实现使用 `Qt::FramelessWindowHint`。Windows 11 人工验证确认窗口能够拖动、缩放、最小化、最大化和还原，但鼠标拖到屏幕边缘时不会贴靠，`Win + 左/右方向键` 也不会贴靠；同一系统中的原生应用能够正常使用这两种贴靠方式。运行时检查同时排除了系统贴靠被关闭和窗口最小宽度超过半屏宽度。

Qt 6.11 的 Windows 平台实现把 `Qt::FramelessWindowHint` 顶层窗口映射为不带可调整系统边框的弹出窗口，因此 Windows 不把该窗口识别为左右贴靠候选。相关实现可参考 Qt 6.11 的 [`qwindowswindow.cpp`](https://code.qt.io/cgit/qt/qtbase.git/plain/src/plugins/platforms/windows/qwindowswindow.cpp?h=6.11)。项目仍不直接调用或依赖其中的 Windows API；该源码只用于解释公开 Qt 窗口标志在基线版本上的实际平台行为。

曾提议让 Windows 主窗口不再设置 `Qt::FramelessWindowHint`，改为使用 `Qt::CustomizeWindowHint`，移除 `Qt::WindowTitleHint`，并显式保留 `Qt::WindowSystemMenuHint`、`Qt::WindowMinimizeButtonHint`、`Qt::WindowMaximizeButtonHint` 和 `Qt::WindowCloseButtonHint`。实现测试证明该组合不能用于 `QMainWindow`：Qt Widgets 的 `QWidgetPrivate::adjustFlags()` 会在 Windows 非对话框窗口包含最小化、最大化、关闭或上下文帮助按钮标志时，强制加入 `Qt::WindowTitleHint` 并移除 `Qt::FramelessWindowHint`。相关实现可参考 Qt 6.11 的 [`qwidget.cpp`](https://code.qt.io/cgit/qt/qtbase.git/plain/src/widgets/kernel/qwidget.cpp?h=6.11)。

因此，当前 Qt 6.11.2 `QMainWindow` 公开接口不能同时满足“完全自定义标题栏”“保留 Windows 鼠标和键盘贴靠资格”以及“保留标准主窗口类型和系统窗口能力标志”。本次修订决定保留标准 `QMainWindow` 类型和系统窗口能力，通过 Windows 专用适配层移除原生标题栏视觉并向系统报告可拖动标题栏区域；不再使用 `Qt::FramelessWindowHint`，也不手写窗口移动、贴靠或贴靠布局。

## 范围

M5 包含：

- 在 Windows 主窗口保留标准可调整尺寸窗口样式，并通过 Windows 专用适配层隐藏原生标题栏
- 独立的自定义标题栏组件，显示当前窗口标题
- 最小化、最大化或还原、关闭三个窗口按钮
- 使用 `QStyle::standardIcon()` 提供的标题栏标准图标，并随窗口状态切换最大化或还原图标
- 在标题栏可拖动区域向 Windows 返回原生标题栏命中结果，由系统发起窗口拖动、最大化拖回和贴靠
- 双击标题栏可拖动区域切换最大化和还原
- 在普通窗口状态下保留 Windows 标准边框缩放，并继续使用 Qt 逻辑像素定义四边和四角命中区域
- 根据窗口状态和指针所在边缘更新按钮状态及缩放光标
- 保持现有动态窗口标题、最小尺寸、关闭清理和主界面布局行为
- 自动测试及 Windows 人工界面验证

M5 不包含：

- 把目标语言选择器或其他业务操作移入标题栏
- 标题栏右键菜单或自定义系统菜单
- 除本文“Windows 原生适配边界”明确列出的窗口样式和消息外的 Win32、DWM 或其他平台原生代码
- Windows 11 最大化按钮悬停时的原生 Snap Layout 弹层复刻；通过系统拖动产生的窗口贴靠仍在范围内
- Mica、Acrylic、透明模糊、自定义阴影、特殊圆角或主题系统
- 自定义应用图标和品牌视觉重设计
- 无边框对话框；文件选择器、消息框和其他对话框继续使用现有窗口框架
- Linux 和 macOS 的无边框启用、视觉适配及人工验收
- 窗口位置、尺寸或最大化状态的跨重启持久化

## 用户工作流

1. 用户在 Windows 启动 MNCE，主窗口显示自定义标题栏而不是原生标题栏。
2. 标题栏显示当前窗口标题；进入和离开媒体详情时继续反映现有动态标题。
3. 用户拖动标题栏按钮之外的区域移动窗口，并可使用 Windows 的拖动贴靠。
4. 用户双击可拖动区域或点击最大化按钮，在最大化与普通状态间切换。
5. 用户在普通状态从窗口四边或四角调整尺寸；最大化状态不显示缩放光标，也不发起缩放。
6. 用户可以最小化或关闭窗口；关闭仍经过现有 `closeEvent()` 清理流程。

## Qt 与 Windows 接口边界

### Qt 接口选择

- Windows 主窗口不再使用 `Qt::FramelessWindowHint`；其他平台的窗口标志不变。
- `QWindow::startSystemMove()` 和 `QWindow::startSystemResize()` 保留为通用控制逻辑的能力边界，但 Windows 主窗口优先通过原生非客户区命中让系统接管移动和缩放，不通过连续调用 `QWidget::move()` 或 `resize()` 模拟。
- 最小化、最大化和还原使用 Qt 的 `showMinimized()`、`showMaximized()` 和 `showNormal()`；关闭使用 `close()`。
- 标题文本以 `QWidget::windowTitle` 为单一来源，自定义标题栏响应 `windowTitleChanged`，不建立第二套页面标题状态。
- 标题栏按钮图标使用 `QStyle` 标准图标 `SP_TitleBarMinButton`、`SP_TitleBarMaxButton`、`SP_TitleBarNormalButton` 和 `SP_TitleBarCloseButton`。
- 最大化或还原状态根据 Qt 窗口状态事件更新，不根据按钮点击结果自行猜测。
- 平台启用条件使用 Qt 提供的平台宏或等价 Qt 平台判断；标题栏和交互组件本身不包含 Windows 头文件或原生句柄。

上述 Qt 接口选择依据 Qt 6.11.2 官方文档：[QWindow](https://doc.qt.io/qt-6/qwindow.html)、[Qt Window Flags](https://doc.qt.io/qt-6/qt.html#WindowType-enum)、[QStyle](https://doc.qt.io/qt-6/qstyle.html#StandardPixmap-enum)和[QEvent](https://doc.qt.io/qt-6/qevent.html#Type-enum)。

### Windows 原生适配边界

- Windows 专用实现放在独立源文件中，只在 `WIN32` 构建条件下编译；通用标题栏组件和业务目标不包含 Windows 头文件。
- 主窗口保留标准顶层窗口类型、系统菜单、最小化、最大化、关闭及可调整尺寸能力。适配层移除原生标题栏及弹出窗口分类样式，并在样式变化后通知系统重新计算窗口框架。
- 允许使用当前窗口的原生句柄，以及与窗口样式更新直接相关的 `GetWindowLongPtrW()`、`SetWindowLongPtrW()` 和 `SetWindowPos()`；必须保留与本修订无关的既有样式位，不能重建整套样式常量。
- 允许处理 `WM_NCHITTEST`：标题栏可拖动区域返回 `HTCAPTION`，四边和四角返回对应的系统缩放命中结果，标题栏按钮及其他交互控件返回 `HTCLIENT`。
- 允许处理标题栏非客户区右键消息并标记为已处理，确保本里程碑仍不提供标题栏右键菜单；不得借此实现自定义系统菜单。
- 最大化、还原、最小化和关闭继续通过 Qt API 发起；窗口状态和按钮图标继续以 Qt 状态事件为准。
- 不处理或重绘 DWM、阴影、圆角、Snap Layout 弹层及系统贴靠布局；这些行为由 Windows 根据标准窗口样式和命中结果决定。
- 原生处理失败时保持窗口稳定并报告验证失败，不回退到手写移动、缩放或贴靠几何。

### 组件职责

- `ui/` 中的标题栏组件只负责标题、按钮、可拖动区域、双击手势、可访问名称和用户操作信号。
- 独立的通用窗口框架控制逻辑负责平台启用策略、边缘命中判断、光标形状、窗口状态同步，以及调用 `QWindow` 的系统移动和缩放接口。
- Windows 专用适配层只负责原生窗口样式生命周期和非客户区命中；它通过与标题栏组件共享的可拖动区域规则排除按钮及其他交互控件。
- `MainWindow` 只负责装配标题栏、内容区和窗口控制逻辑；现有媒体、播放、语言及持久化服务不感知自定义窗口框架实现。
- 标题栏按钮及其他交互控件不属于拖动区域；在这些控件上按下、双击或右击不得触发窗口移动。
- 所有边缘宽度、标题栏高度和布局间距使用 Qt 逻辑像素及布局系统，不读取或写死设备物理像素。
- `windowHandle()` 不可用或 Qt 的系统移动、缩放请求返回失败时，保持窗口稳定并结束该次操作，不增加手写几何移动作为隐藏回退。

`MainWindow::nativeEvent()` 只允许把 Windows 消息转发给适配层并返回其处理结果，不包含命中、样式或业务判断。其他平台不编译该转发路径。

## 实施检查点

### 检查点一：标题栏与窗口交互边界

包含：

- 自定义标题栏组件及 Qt 标准标题栏图标
- 自定义窗口框架控制逻辑及 Windows 启用策略
- 可拖动区域、双击、边缘和四角命中规则
- 系统移动、系统缩放和窗口状态同步
- 组件与窗口交互逻辑的自动测试

本检查点先建立可独立验证的窗口行为，不调整媒体库或媒体详情工作流。完成后汇报实现和测试结果，经用户确认后再进入检查点二。

### 检查点二：主窗口集成与完整验证

包含：

- 将标题栏和自定义窗口框架控制接入 `MainWindow`
- 保持语言选择器位于内容区，保持当前页面布局和动态窗口标题
- 保持关闭时的播放与后台任务清理
- 主窗口 GUI 端到端测试
- Windows 11 多缩放比例、拖动贴靠和真实窗口交互人工验证

### 修订检查点：恢复 Windows 系统贴靠

包含：

- 用保留系统菜单、最小化、最大化、关闭和可调整尺寸能力的标准 Windows 主窗口样式替换 `Qt::FramelessWindowHint`
- 增加严格限界的 Windows 窗口框架适配层，以及 `MainWindow::nativeEvent()` 的薄转发
- 统一标题栏空白区域、标题栏按钮、内容控件、四边和四角的原生命中规则
- 保持标题栏无右键菜单、Qt 窗口状态同步、动态标题及关闭清理行为
- 增加 Windows 适配层自动测试，并运行现有组件、GUI 和关闭清理回归测试
- 重新完成 Windows 11 鼠标拖动贴靠、键盘贴靠、缩放比例和真实窗口交互人工验证

本修订检查点只解决首版实现暴露的 Windows 系统贴靠资格问题，不扩展标题栏功能或视觉范围。实现、自动验证和本文列出的 Windows 人工验证均已完成。

## 测试

M5 遵守[测试策略](testing-strategy.md)。自动测试验证 Qt 内部可确定观察的行为；需要窗口管理器参与的真实移动、缩放和贴靠由 Windows 人工检查覆盖，不使用依赖桌面环境时序的自动化断言。

自动测试至少覆盖：

- 普通、最大化和还原状态下按钮图标与可用状态同步
- 最小化、最大化、还原和关闭按钮触发对应窗口操作
- 标题随顶层窗口 `windowTitle` 变化而更新
- 标题栏空白区域可以请求移动，按钮及其他交互控件不会请求移动
- 双击可拖动区域切换最大化和还原，双击按钮区域不触发切换
- 四边、四角和非边缘位置映射到正确的 `Qt::Edges`
- 普通状态返回系统缩放命中结果，最大化状态不返回缩放命中结果
- Windows 主窗口保留可调整尺寸、系统菜单、最小化、最大化和关闭能力，并移除原生标题栏视觉；其他平台默认保留原生标题栏
- 标题栏空白区域、标题栏按钮、内容控件、四边和四角映射到正确的 Windows 非客户区命中结果
- 标题栏非客户区右键不会显示菜单；键盘系统窗口操作不被适配层拦截
- 现有媒体详情播放与主窗口关闭回归测试继续通过

GUI 端到端测试至少覆盖：

- Windows 主窗口显示自定义标题栏、三个窗口按钮和内容区语言选择器
- 进入媒体详情及返回媒体库时，自定义标题文字与现有窗口标题保持一致
- 点击最大化和还原后布局仍可使用，按钮图标同步变化
- 点击关闭后仍执行播放器和后台任务的安全清理

Windows 人工验证至少覆盖：

- 100%、125%、150% 和 200% 显示缩放下的标题、图标、命中区域及布局
- 普通、最小化、最大化、还原和 `Alt+F4` 关闭
- 标题栏拖动、从最大化状态拖动、屏幕边缘贴靠及贴靠后恢复
- `Win + 左/右方向键` 能够贴靠，`Win + 上/下方向键` 的最大化、还原和最小化行为正常
- 四边和四角缩放、最小窗口尺寸限制，以及最大化状态不出现缩放行为
- 标题栏按钮、语言选择器和页面控件不会误触发拖动或缩放
- 原生文件选择器和消息框仍能正常显示、聚焦并归属于主窗口

## 验收标准

1. Windows 11 主窗口不显示原生标题栏，并提供清晰可用的自定义标题栏。
2. 最小化、最大化、还原、关闭、双击切换、拖动贴靠及八方向缩放均按本文规则工作。
3. 标题栏不包含语言选择器且不提供右键菜单；语言选择器和现有业务界面保持可用。
4. 除独立的 Windows 窗口框架适配层及 `MainWindow::nativeEvent()` 薄转发外，实现使用 Qt 公开接口且不包含 Windows 头文件、原生句柄或平台消息处理；原生适配只使用本文列出的窗口样式更新、非客户区命中和右键抑制能力，不使用 DWM、业务逻辑或手写贴靠几何。
5. 其他目标平台默认保留原生标题栏，M5 不改变其既有窗口行为。
6. 动态窗口标题、最小尺寸、媒体播放、关闭清理、原生对话框和现有导航没有回归。
7. 新增组件和 GUI 自动测试均由 CTest 发现并通过。
8. Debug 和 Release 构建无新增编译器警告并成功构建。
9. 在 Windows 11 基线环境完成本文列出的人工界面和窗口交互检查。
