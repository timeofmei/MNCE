# M5：Windows 自定义标题栏

> 状态：草案，待确认。本文只定义 M5 的目标、范围和验收标准；确认前不开始实现。

## 目标

在 Windows 基线环境隐藏主窗口原生标题栏，提供与 MNCE 主界面一致的自定义标题栏，同时保留最小化、最大化、还原、关闭、拖动、系统贴靠和边缘缩放等基础桌面窗口行为。

M5 优先依赖 Qt 6.11.2 的公开跨平台接口。自定义标题栏组件和窗口交互逻辑不依赖 Win32、DWM 或 Windows 消息；本阶段只在 Windows 启用和验收，其他目标平台继续使用原生标题栏，待各平台单独验证后再决定是否启用。

## 已确认决策

- M5 先支持 Windows 11，平台和工具链基线沿用[平台、发行与许可证](platform-and-distribution.md)。
- 实现尽量通用并优先使用 Qt 提供的功能和接口，不调用 Windows 专有接口。
- 自定义标题栏不放目标语言选择器；现有选择器继续位于主窗口内容区左上角，符合[页面与导航](ui-structure.md)的既有规则。
- 不提供标题栏右键菜单。

## 范围

M5 包含：

- 在 Windows 主窗口使用 `Qt::FramelessWindowHint` 隐藏原生窗口框架
- 独立的自定义标题栏组件，显示当前窗口标题
- 最小化、最大化或还原、关闭三个窗口按钮
- 使用 `QStyle::standardIcon()` 提供的标题栏标准图标，并随窗口状态切换最大化或还原图标
- 在标题栏可拖动区域通过 `QWindow::startSystemMove()` 发起系统窗口拖动
- 双击标题栏可拖动区域切换最大化和还原
- 在普通窗口状态下，通过 `QWindow::startSystemResize()` 支持四边和四角缩放
- 根据窗口状态和指针所在边缘更新按钮状态及缩放光标
- 保持现有动态窗口标题、最小尺寸、关闭清理和主界面布局行为
- 自动测试及 Windows 人工界面验证

M5 不包含：

- 把目标语言选择器或其他业务操作移入标题栏
- 标题栏右键菜单或自定义系统菜单
- Win32 消息处理、`nativeEvent()`、`HWND`、`WM_NCHITTEST`、DWM 接口或其他平台原生代码
- Windows 11 最大化按钮悬停时的原生 Snap Layout 弹层复刻；通过系统拖动产生的窗口贴靠仍在范围内
- Mica、Acrylic、透明模糊、自定义阴影、特殊圆角或主题系统
- 自定义应用图标和品牌视觉重设计
- 无边框对话框；文件选择器、消息框和其他对话框继续使用现有窗口框架
- Linux 和 macOS 的无边框启用、视觉适配及人工验收
- 窗口位置、尺寸或最大化状态的跨重启持久化

## 用户工作流

1. 用户在 Windows 启动 MNCE，主窗口显示自定义标题栏而不是原生标题栏。
2. 标题栏显示当前窗口标题；进入和离开媒体详情时继续反映现有动态标题。
3. 用户拖动标题栏按钮之外的区域移动窗口，并可使用 Windows 的拖动贴靠。
4. 用户双击可拖动区域或点击最大化按钮，在最大化与普通状态间切换。
5. 用户在普通状态从窗口四边或四角调整尺寸；最大化状态不显示缩放光标，也不发起缩放。
6. 用户可以最小化或关闭窗口；关闭仍经过现有 `closeEvent()` 清理流程。

## Qt 接口与职责边界

### Qt 接口选择

- 无边框窗口使用 `Qt::FramelessWindowHint`，不自行修改原生窗口样式。
- 移动与缩放分别使用 `QWindow::startSystemMove()` 和 `QWindow::startSystemResize()`，让窗口系统接管交互，不通过连续调用 `QWidget::move()` 或 `resize()` 模拟。
- 最小化、最大化和还原使用 Qt 的 `showMinimized()`、`showMaximized()` 和 `showNormal()`；关闭使用 `close()`。
- 标题文本以 `QWidget::windowTitle` 为单一来源，自定义标题栏响应 `windowTitleChanged`，不建立第二套页面标题状态。
- 标题栏按钮图标使用 `QStyle` 标准图标 `SP_TitleBarMinButton`、`SP_TitleBarMaxButton`、`SP_TitleBarNormalButton` 和 `SP_TitleBarCloseButton`。
- 最大化或还原状态根据 Qt 窗口状态事件更新，不根据按钮点击结果自行猜测。
- 平台启用条件使用 Qt 提供的平台宏或等价 Qt 平台判断；标题栏和交互组件本身不包含 Windows 头文件或原生句柄。

上述接口选择依据 Qt 6.11.2 官方文档：[QWindow](https://doc.qt.io/qt-6/qwindow.html)、[Qt Window Flags](https://doc.qt.io/qt-6/qt.html#WindowType-enum)、[QStyle](https://doc.qt.io/qt-6/qstyle.html#StandardPixmap-enum)和[QEvent](https://doc.qt.io/qt-6/qevent.html#Type-enum)。

### 组件职责

- `ui/` 中的标题栏组件只负责标题、按钮、可拖动区域、双击手势、可访问名称和用户操作信号。
- 独立的无边框窗口控制逻辑负责 Windows 启用策略、边缘命中判断、光标形状、窗口状态同步，以及调用 `QWindow` 的系统移动和缩放接口。
- `MainWindow` 只负责装配标题栏、内容区和窗口控制逻辑；现有媒体、播放、语言及持久化服务不感知无边框实现。
- 标题栏按钮及其他交互控件不属于拖动区域；在这些控件上按下、双击或右击不得触发窗口移动。
- 所有边缘宽度、标题栏高度和布局间距使用 Qt 逻辑像素及布局系统，不读取或写死设备物理像素。
- `windowHandle()` 不可用或 Qt 的系统移动、缩放请求返回失败时，保持窗口稳定并结束该次操作，不增加手写几何移动作为隐藏回退。

## 实施检查点

### 检查点一：标题栏与窗口交互边界

包含：

- 自定义标题栏组件及 Qt 标准标题栏图标
- 无边框窗口控制逻辑及 Windows 启用策略
- 可拖动区域、双击、边缘和四角命中规则
- 系统移动、系统缩放和窗口状态同步
- 组件与窗口交互逻辑的自动测试

本检查点先建立可独立验证的窗口行为，不调整媒体库或媒体详情工作流。完成后汇报实现和测试结果，经用户确认后再进入检查点二。

### 检查点二：主窗口集成与完整验证

包含：

- 将标题栏和无边框控制接入 `MainWindow`
- 保持语言选择器位于内容区，保持当前页面布局和动态窗口标题
- 保持关闭时的播放与后台任务清理
- 主窗口 GUI 端到端测试
- Windows 11 多缩放比例、拖动贴靠和真实窗口交互人工验证

## 测试

M5 遵守[测试策略](testing-strategy.md)。自动测试验证 Qt 内部可确定观察的行为；需要窗口管理器参与的真实移动、缩放和贴靠由 Windows 人工检查覆盖，不使用依赖桌面环境时序的自动化断言。

自动测试至少覆盖：

- 普通、最大化和还原状态下按钮图标与可用状态同步
- 最小化、最大化、还原和关闭按钮触发对应窗口操作
- 标题随顶层窗口 `windowTitle` 变化而更新
- 标题栏空白区域可以请求移动，按钮及其他交互控件不会请求移动
- 双击可拖动区域切换最大化和还原，双击按钮区域不触发切换
- 四边、四角和非边缘位置映射到正确的 `Qt::Edges`
- 普通状态能够请求系统缩放，最大化状态不请求缩放
- Windows 构建启用无边框主窗口；其他平台默认保留原生标题栏
- 现有媒体详情播放与主窗口关闭回归测试继续通过

GUI 端到端测试至少覆盖：

- Windows 主窗口显示自定义标题栏、三个窗口按钮和内容区语言选择器
- 进入媒体详情及返回媒体库时，自定义标题文字与现有窗口标题保持一致
- 点击最大化和还原后布局仍可使用，按钮图标同步变化
- 点击关闭后仍执行播放器和后台任务的安全清理

Windows 人工验证至少覆盖：

- 100%、125%、150% 和 200% 显示缩放下的标题、图标、命中区域及布局
- 普通、最小化、最大化、还原和 `Alt+F4` 关闭
- 标题栏拖动、从最大化状态拖动、屏幕边缘贴靠及贴靠后恢复
- 四边和四角缩放、最小窗口尺寸限制，以及最大化状态不出现缩放行为
- 标题栏按钮、语言选择器和页面控件不会误触发拖动或缩放
- 原生文件选择器和消息框仍能正常显示、聚焦并归属于主窗口

## 验收标准

1. Windows 11 主窗口不显示原生标题栏，并提供清晰可用的自定义标题栏。
2. 最小化、最大化、还原、关闭、双击切换、拖动贴靠及八方向缩放均按本文规则工作。
3. 标题栏不包含语言选择器且不提供右键菜单；语言选择器和现有业务界面保持可用。
4. 实现只使用 Qt 公开接口，不包含 Windows 头文件、原生句柄、原生事件或平台消息处理。
5. 其他目标平台默认保留原生标题栏，M5 不改变其既有窗口行为。
6. 动态窗口标题、最小尺寸、媒体播放、关闭清理、原生对话框和现有导航没有回归。
7. 新增组件和 GUI 自动测试均由 CTest 发现并通过。
8. Debug 和 Release 构建无新增编译器警告并成功构建。
9. 在 Windows 11 基线环境完成本文列出的人工界面和窗口交互检查。
