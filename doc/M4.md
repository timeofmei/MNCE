# M4：本地音频播放基础

> 状态：已确认。本文目标、范围和验收标准作为 M4 实现基线。

## 目标

在 M3 媒体库基础上增加统一媒体详情与本地音频播放，使用户能够从单文件或系列条目进入详情，查看时长并完成整段音频的播放、暂停、跳转和倍速控制。

长期播放行为由[音频播放](audio-playback.md)统一定义。M4 只实现整段播放基础，不提前实现学习模式中的逐句播放和录音。

## 范围

M4 包含：

- 单文件和系列媒体名称进入统一媒体详情页
- 当前媒体基本信息、路径、文件状态、识别状态和时长展示
- 播放、暂停、当前位置、总时长和进度跳转
- 固定档位倍速控制
- 倍速应用级偏好的保存与恢复
- 文件缺失、格式不支持、无权限和解码失败的界面状态
- schema version 3 时长字段迁移
- 可替换播放边界、Qt Multimedia 生产实现及自动测试
- Windows 基线环境的真实音频人工验证

M4 不包含：

- FFmpeg API 的直接集成或 whisper.cpp 所需 PCM 解码
- 内容哈希、扫描或媒体身份规则的改变
- 自动播放、播放列表、上一首或下一首
- 断点续播和播放位置持久化
- 波形、频谱、均衡器和音频输出设备选择
- 应用内音量控制
- 逐句播放、AB 循环、单句循环和句间静音
- 麦克风录音、跟读、听写和背诵流程
- 转写、分句、模型管理和发行打包

## 用户工作流

1. 用户点击单文件或系列媒体名称进入详情。
2. 详情立即展示数据库中的已有信息，并异步加载本地音频。
3. 已保存的时长可立即显示；未知时长先显示 `—`，加载成功后更新并保存。
4. 用户主动点击播放，通过同一控制区暂停、跳转和调速；音量由操作系统或音频输出设备控制。
5. 切换到其他媒体时停止当前播放并加载新媒体，但不自动播放。
6. 文件缺失或加载失败时禁用不可用控制并显示明确原因，不触发哈希或更改媒体身份。

## 持久化与迁移

M4 将数据库升级为 schema version 3：

- `media_items` 增加 `duration_ms INTEGER NULL CHECK (duration_ms >= 0)`。
- `series_media_items` 增加相同字段。
- version 2 升级必须在一个事务中完成，不修改现有媒体 ID、哈希、路径、语言和状态。
- 迁移成功后设置 `PRAGMA user_version = 3`；失败时完整回滚。
- 全新数据库直接得到 version 3 schema；重复初始化不改变已有数据。
- 仓储分别提供按媒体 ID 更新时长的接口，并验证记录存在及数值合法。

倍速保存在现有应用设置中，不写入媒体表；其语义、支持档位和默认值见[音频播放](audio-playback.md)。具体设置键在实现时沿用项目现有命名方式，不构成持久化兼容接口。

## 代码与职责边界

- `domain/` 增加播放状态、媒体来源引用和时间格式化等不依赖 UI、SQL 或 Qt Multimedia 后端的类型与逻辑。
- `persistence/` 负责 version 3 迁移和两类媒体时长更新，不保存瞬时播放状态或位置。
- `services/` 提供统一播放器控制器和可替换后端接口，隔离 `QMediaPlayer`、`QAudioOutput` 与界面。
- `ui/` 负责编排详情导航、控件状态、偏好保存和用户反馈，不直接推断后端状态。
- 生产播放对象遵守 Qt 对象线程归属；关闭窗口时先停止播放器并断开回调。
- 每次加载分配递增请求标识或等价令牌，忽略已切换媒体的迟到回调。

## 实施检查点

### 检查点一：数据与播放边界

包含：

- schema version 3 迁移和时长仓储接口
- 播放领域状态、时间格式化与设置值校验
- 可替换播放后端及基于 Qt Multimedia 的生产实现
- 播放器控制器的加载、状态转换、跳转、倍速、错误和迟到回调处理
- 领域、迁移、持久化和服务层自动测试

本检查点不接入正式媒体详情界面。完成后先汇报实现和测试结果，经用户确认后再进入检查点二。

### 检查点二：详情界面与完整工作流

包含：

- 单文件和系列媒体名称的详情入口
- 统一媒体详情及播放器控件
- 时长更新后同步刷新列表与详情
- 缺失、不可跳转、加载中和错误状态
- 倍速偏好保存和恢复
- 使用替换后端的 GUI 端到端测试
- Windows 真实音频和界面人工验证

## 测试

M4 遵守[测试策略](testing-strategy.md)。自动测试使用临时数据库、临时设置和运行时生成的短 WAV；服务与 GUI 测试使用替换播放后端，不依赖真实声卡、网络或系统编解码器。

至少覆盖：

- version 2 升级保留单文件和系列媒体数据，迁移失败完整回滚
- 空时长、合法时长和非法时长的持久化规则
- 时间显示在分钟及超过一小时情况下的格式
- 加载、播放、暂停、生命周期停止、结束和错误状态转换
- 可跳转与不可跳转媒体的进度行为
- 倍速档位、默认值、非法设置回退及跨重启恢复
- 切换媒体后忽略旧媒体迟到回调
- 打开详情不自动播放、不触发哈希且不改变媒体身份
- 文件缺失时禁用播放；重新定位后可以重新加载
- 单文件和系列媒体共用播放流程但保持各自数据归属

GUI 端到端测试至少覆盖：

- 从单文件名称进入详情，加载后播放、暂停和跳转
- 从系列媒体名称切换到另一条媒体，旧播放停止且新媒体不自动播放
- 调整倍速后重启窗口能够恢复
- 后端加载失败时显示错误并保持界面可继续操作

Windows 人工验证至少覆盖一个 WAV、一个 MP3 和一个其他计划格式，检查真实播放、拖动进度、倍速、默认输出设备、窗口尺寸和显示缩放。

## 验收标准

1. 用户可以从单文件和系列媒体进入统一详情并主动播放本地音频。
2. 播放、暂停、进度、时间和倍速符合[音频播放](audio-playback.md)规则，界面不提供停止或音量控制。
3. 打开详情不自动播放、不触发哈希；切换媒体停止旧播放且不保留位置。
4. 已知时长可以持久化并显示；未知时长不会阻塞媒体库加载。
5. 文件缺失或播放失败时提供明确状态，不改变媒体身份或其他容器数据。
6. version 2 数据库可以安全升级到 version 3，失败能够回滚。
7. 播放服务可在无真实声卡和解码器的情况下进行确定性测试。
8. 新增单元、组件和 GUI 端到端测试均由 CTest 发现并通过。
9. Debug 和 Release 构建无新增编译器警告并成功构建。
10. 在 Windows 基线环境完成真实音频与人工界面检查。
