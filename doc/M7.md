# M7：Whisper 模型管理

> 状态：已确认。本文目标、范围、决策和验收标准作为 M7 实现基线。

## 目标

在现有媒体库和媒体详情基础上增加 Whisper 模型管理，使用户能够查看与目标语言兼容的内置模型，完成下载、完整性校验、取消、失败重试和删除，并让应用可靠查询当前已安装模型及自动选择结果，为后续本地语音识别里程碑提供稳定边界。

模型目录、语言兼容关系和自动选择规则由[媒体库与语音识别](media-and-transcription.md#whisper-模型)统一定义；目标语言切换与异步任务归属遵守[目标语言与内容空间](target-languages.md)。M7 不执行语音识别，也不提前建立转写任务。

## 已确定边界

- 只展示应用内置模型目录，不允许导入任意模型或填写自定义下载地址。
- 安装包不携带模型；模型由用户主动下载，不静默下载。
- 每个目录项必须固定模型标识、版本、参数量等级、量化方式、文件名、下载大小、支持语言、来源提交、上游与国内镜像 HTTPS 下载地址、SHA-256 和许可证信息。
- 发布目录不得使用随时间变化的分支地址。模型文件只有在完整下载并通过 SHA-256 校验后才视为已安装。
- 下载来源只提供“官方源（huggingface.co）”和“国内镜像（hf-mirror.net）”两项，具体地址与切换边界以[媒体库与语音识别](media-and-transcription.md#whisper-模型)为准；不允许自定义地址，也不静默自动切换来源。
- 首次启动默认选择官方源；用户之后的明确选择作为应用级偏好跨重启保存，并在所有目标语言空间中共用。
- 模型文件存放在系统标准应用数据目录下，不写入程序目录、源码目录、当前工作目录或媒体文件所在目录。
- 模型安装状态是应用级状态，不属于某个媒体容器或目标语言空间；目标语言只决定兼容模型的展示与选择。
- 普通模型管理页只展示支持当前目标语言的模型；每个模型仍列出它支持的全部语言。
- 同一时间只允许一个模型下载，不建立并行下载或等待队列；活动下载结束或取消前，其他模型不能开始下载。
- 模型下载大小统一以 MiB 为单位展示，不使用 MB 或 GB；换算规则由[媒体库与语音识别](media-and-transcription.md#whisper-模型)定义。
- 下载支持同一来源的跨重试和跨应用重启断点续传；用户主动取消或切换来源时不保留可续传文件，具体响应校验规则以[媒体库与语音识别](media-and-transcription.md#whisper-模型)为准。
- 删除已安装模型前必须二次确认，显示模型大小和重新下载影响，并明确该操作不删除媒体、原始音频或已有识别结果。
- M7 只使用系统标准应用数据目录存放模型，不提供自定义存储位置或现有文件迁移；这些能力留待设置页里程碑统一设计。
- 首版内置目录包含规范中确定的 `base.en-q8_0`、`small-q8_0`、`medium-q8_0` 和 `large-v3-q5_0` 四个模型，不先缩减为测试子集。
- 自动选择只考虑支持目标语言且完整性有效的已安装模型，并遵守规范中的参数量优先级；量化方式不改变参数量等级。
- 下载、校验和文件操作不得阻塞 UI 线程。网络错误不得导致已有有效模型损坏。

M7 包含：

- 固定且可测试的内置模型目录及目录校验

- 无效或损坏文件的明确状态及重新下载入口
- 删除已安装模型文件
- 模型管理一级页面及从现有主窗口进入和返回的导航

- 安装包、运行时依赖部署和正式发行验证

## 用户工作流

1. 用户从主窗口进入模型管理，页面按照当前目标语言展示可用的内置模型及其名称、版本、大小、兼容语言、许可证和安装状态。
2. 用户在“官方源（huggingface.co）”和“国内镜像（hf-mirror.net）”之间选择下载来源；该选择只影响之后新建的下载任务，不改变已经开始的任务。
3. 用户选择一个未安装模型并主动开始下载；界面显示确定或不确定进度，并提供取消操作。
4. 下载写入临时文件。完成后应用在后台计算 SHA-256；只有校验通过才将文件原子移动到正式位置并显示“已安装”。
5. 用户取消下载时任务停止，未完成文件被清理，模型恢复为“未安装”。
6. 网络中断或应用退出时保留未完成文件；用户从同一来源重试时从已保存位置继续下载。服务端不正确支持本次 Range 请求时，应用丢弃未完成文件并安全地从头下载。
7. 下载或校验失败时页面显示可操作的失败原因；用户可以同源续传，也可以明确选择另一个来源后从头开始，其他模型和媒体数据不受影响。
8. 用户删除已安装模型后，应用只删除受管理的模型文件，不删除媒体、音频或已经保存的业务数据。
9. 用户切换目标语言时页面刷新兼容模型；已经开始的下载不改变目标模型，也不因语言切换而写入另一套副本。
10. 用户离开模型页面时下载继续；关闭应用时安全停止活动请求并保留可续传的未完成文件。

## 模型目录与选择

- 内置目录作为只读应用资源或编译期数据随版本发布，不通过网络替换其元数据。
- 目录中的稳定模型标识不得由显示名称、下载文件名或本地路径临时推导。
- 目录初始化时拒绝重复模型标识、重复正式文件名、空版本、空校验值、非 HTTPS 地址、官方与镜像路径不对应、格式非法或重复的语言标识，以及不完整许可证元数据。模型可以提前声明尚未加入当前目标语言目录的兼容语言。
- 两个来源必须指向同一 Hugging Face 仓库提交和相同文件路径；下载服务不得从镜像响应动态替换内置模型元数据。
- 模型支持语言使用目标语言目录提供的稳定 BCP 47 ID；通用查询逻辑不为英语或日语编写分支。
- 自动选择服务接收明确的目标语言 ID 和安装快照，不读取当前 UI 语言作为隐藏输入。
- 没有兼容的有效已安装模型时返回结构化的“缺少兼容模型”结果，不在服务内部启动下载或打开界面。
- M7 实现前必须锁定本版本实际发布的模型清单、来源提交、文件大小和 SHA-256；候选范围仍以规范所有者为准，不在本文复制第二份模型表。

## 存储与文件完整性

- 模型服务只允许操作模型根目录内由内置目录声明的正式文件和临时文件；任何由目录穿越、绝对文件名或符号链接导致的越界目标都必须拒绝。
- 正式文件存在时计算完整 SHA-256。哈希匹配才标记为已安装；大小可以用于提前发现明显错误，但不能代替完整哈希。
- 下载始终写入同一文件系统中的专用未完成文件，校验成功后原子替换正式目标，避免复制中断留下看似已安装的文件。
- 未完成文件必须能关联到模型标识、创建时选择的来源、固定提交、正式文件名和预期总大小；信息不完整或与当前内置目录不一致时不得续传。
- 应用启动时检查受管理模型目录中的未完成文件。元数据和长度有效时将其显示为可继续下载；无法识别、越界、超过预期大小或与当前目录不一致时安全删除。
- 校验失败的完整下载文件不得成为正式模型，也不得继续作为断点数据；失败信息区分网络、取消、磁盘写入、空间不足和完整性校验失败。
- 已有有效模型在重新检查或其他模型下载失败时保持不变。
- 模型安装状态从目录和磁盘事实派生，M7 不为下载进度或安装状态升级 SQLite schema。
- 自动测试通过注入临时模型根目录运行，不访问真实用户模型目录。

## 下载边界与生命周期

- 生产下载器使用 Qt Network，根据用户明确选择的来源解析当前模型的固定 URL，跟随受控 HTTPS 重定向但拒绝降级到明文 HTTP。
- 下载控制器通过可替换接口接收模型元数据、来源、进度、完成、取消和结构化失败，不把 `QNetworkReply` 暴露给 UI。
- 下载任务创建时保存来源；用户之后切换来源不会改变活动请求。下载失败后只有用户明确重试才创建新请求，不自动改用另一个来源。
- 同源续传发送从未完成文件当前长度开始的 Range 请求。只有 `206 Partial Content` 及匹配的 `Content-Range` 才能追加；服务端返回完整响应或范围信息不匹配时关闭并删除旧文件，然后从头开始，不能把完整响应追加到旧内容。
- 用户主动取消时关闭并删除未完成文件。网络失败、可恢复的写入中断或应用关闭时安全关闭文件但保留它；换源重试前删除旧来源的未完成文件。
- 下载文件以流式方式写盘，不把完整模型保存在内存中；SHA-256 校验也使用分块读取。
- 所有异步回调携带模型标识和请求令牌；取消、重试或切换页面后忽略旧请求的迟到回调。
- 应用关闭时先终止活动请求并安全关闭未完成文件，再销毁网络对象；下次启动通过保存的任务元数据恢复可续传状态，但不自动开始网络请求。
- 自动测试使用可控的替换下载器模拟进度、网络失败、校验失败、取消和迟到回调，不访问真实网络或下载大型模型。

## 页面与状态

- 模型管理作为一级页面加入现有 `QStackedWidget` 导航，不嵌入媒体详情，也不创建独立顶层窗口。
- 页面保留全局目标语言选择器，并提供明确返回媒体库的入口。
- 页面提供只有“官方源（huggingface.co）”和“国内镜像（hf-mirror.net）”两项的下载来源选择器，明确标识国内镜像为第三方服务；不展示或接受任意 URL。
- 每个模型至少展示显示名称、版本、量化方式、预计大小、支持语言、来源与许可证、当前状态以及当前可用操作。
- 状态至少覆盖“未安装”“下载中”“校验中”“已安装”“文件损坏”和“失败”。下载中显示已接收字节；服务器提供可靠总大小时同时显示百分比。
- 下载、取消、重试和删除按钮由当前状态驱动；重复点击不得创建重复请求或并发写入同一目标文件。
- 失败信息在对应模型附近显示并提供恢复动作，不依赖控制台输出，也不阻塞其他页面操作。
- 页面销毁或离开不拥有下载任务生命周期；任务由应用级控制器持有，返回页面后恢复显示当前状态。

## 代码与职责边界

- `domain/` 定义模型描述、参数量等级、安装状态、选择结果及不依赖网络、文件系统或 UI 的目录规则。
- `services/` 负责模型目录查询、存储检查、哈希校验、下载生命周期和最佳已安装模型选择，并为网络和文件边界提供可替换接口。
- `ui/` 只根据服务快照呈现状态和发起用户操作，不直接读写模型文件、不拼接下载 URL，也不自行判断安装成功。
- 模型下载与媒体导入任务相互独立；M7 不扩展现有媒体 SQLite 仓储或改变媒体身份规则。
- 生产代码使用 Qt 对象线程归属或受控后台任务，确保网络对象在所属线程销毁，文件哈希不占用 UI 线程。

## 测试

M7 遵守[测试策略](testing-strategy.md)。自动测试不访问网络、真实应用数据目录或大型模型；运行时生成小文件和确定性内容来模拟模型下载及 SHA-256。

领域和服务测试至少覆盖：

- 模型目录拒绝重复标识、重复文件名、非法或不对应的官方与镜像地址、非法语言标识和不完整元数据，同时允许模型声明尚未加入当前产品目录的规范语言 ID
- 官方源和国内镜像为同一模型解析出相同提交及文件路径，切换来源不改变预期大小和 SHA-256
- 模型大小按固定文件字节数换算并以 MiB 展示
- 增加第三种测试语言不需要修改目录查询或选择逻辑
- 兼容过滤和 Base、Small、Medium、Large-v3 参数量优先级
- 不存在、有效、大小错误、哈希错误和读取失败的模型文件状态
- 大小不能代替 SHA-256 判断安装有效性
- 流式下载成功、未知总大小进度、取消、网络失败、磁盘失败和校验失败
- 同源重试和重启后从正确偏移续传，正确处理匹配的 `206 Partial Content` 与 `Content-Range`
- 服务端忽略 Range、返回错误起点或总大小时不追加旧内容，而是丢弃未完成文件并从头下载
- 主动取消删除未完成文件，网络中断和应用关闭保留有效未完成文件，换源重试不跨源复用
- 校验完成前不暴露正式文件，成功后原子完成且已有有效模型不受失败任务影响
- 重复请求、重试、取消后迟到回调和应用关闭清理
- 活动任务固定使用创建时选择的来源，失败时不会静默切换，用户明确换源后的重试使用新来源
- 所有文件操作都限制在注入的模型根目录内

GUI 端到端测试至少覆盖：

- 从媒体库进入模型管理并返回，当前目标语言和媒体页面状态保持稳定
- 当前语言只显示按确认策略允许展示的模型，并呈现完整模型信息
- 来源选择器只包含“官方源（huggingface.co）”和“国内镜像（hf-mirror.net）”，首次使用官方源并跨重启保存用户选择，且切换不影响活动下载
- 下载过程中显示进度并可取消，返回页面后状态一致
- 活动下载期间其他模型不能开始下载，且不会形成隐藏的等待队列
- 网络中断或重新启动应用后显示可继续状态，同源重试从已有进度继续
- 下载和校验成功后显示已安装并允许删除
- 删除前显示包含模型大小、重新下载影响和数据边界的二次确认，取消确认时文件保持不变
- 网络、磁盘和校验失败显示可操作错误，重试后可以恢复
- 切换目标语言后页面刷新且活动下载不被错误改名、复制或归属
- 关闭窗口时安全停止活动下载，重新启动后可同源继续且未完成文件不会被识别为已安装

人工验证至少覆盖：

- Windows 上分别从官方源和国内镜像下载并校验同一个实际的小模型，结果 SHA-256 一致；中断并重启应用后能够同源续传，主动取消后能够从头重试
- 删除实际模型后文件消失，再次下载可以恢复
- Fedora KDE Wayland 和 Ubuntu GNOME Wayland 上页面布局、状态、进度、焦点和错误信息清晰可用
- 下载期间媒体播放和现有媒体库导航保持响应

## 验收标准

1. 用户可以在模型管理页查看当前目标语言可用的内置模型、完整元数据和实时安装状态。
2. 用户可以在“官方源（huggingface.co）”和“国内镜像（hf-mirror.net）”之间明确选择，首次使用官方源且后续选择跨重启保存；用户可以主动下载、查看进度、取消、换源重试和删除模型，操作期间 UI 保持响应。
3. 只有完整下载且 SHA-256 匹配的模型才被视为已安装；网络失败或异常关闭保留的未完成文件只能用于受校验的同源续传，主动取消和换源会清除它，任何情况都不会留下假安装状态或破坏已有有效模型。
4. 应用可以按明确目标语言查询兼容模型，并从有效已安装模型中稳定选择参数量最大的模型；没有兼容模型时返回结构化结果。
5. 模型文件和临时文件只能位于受管理的模型目录，模型操作不改变媒体、系列、原始音频或 SQLite 数据。
6. 下载不会静默切换来源；下载和文件错误提供明确、可恢复且不泄露敏感信息的用户提示，不依赖控制台输出。
7. 网络、哈希和文件边界可替换，自动测试不访问真实网络、用户目录或大型模型。
8. 新增单元、组件和 GUI 端到端测试均由 CTest 发现并通过。
9. Windows、Fedora KDE Wayland 和 Ubuntu GNOME Wayland 的 Debug 与 Release 构建及全量自动测试通过，无新增编译器警告。
10. Windows 完成实际模型下载、取消、重试、校验和删除检查，Linux 两个基线桌面完成模型页面人工检查。
