# M6：Linux 自定义标题栏

> 状态：已完成。本文目标、范围和验收标准已按两个实施检查点完成验证。

## 目标

在 Linux 主窗口隐藏桌面环境提供的原生标题栏，复用 M5 已有的 MNCE 自定义标题栏和通用窗口控制逻辑。应用层交互与 Windows 保持一致，并在 Fedora KDE Wayland 和 Ubuntu GNOME Wayland 上保留最小化、最大化、还原、关闭、拖动、桌面贴靠和四边四角缩放等基础窗口行为。

“与 Windows 保持一致”指 MNCE 提供相同的标题栏结构、操作入口和状态反馈。贴靠布局、动画、阴影、圆角和桌面快捷键的具体效果由 KWin 或 GNOME Mutter 决定，M6 不复制 Windows 11 的系统视觉或贴靠布局。

## 已确认决策

- Linux 主窗口使用 M5 已有的 `WindowTitleBar` 和 `FramelessWindowController`，不建立 KDE 与 GNOME 两套标题栏。
- Linux 实现仅使用 Qt 公开接口，不使用 X11 API、Wayland 协议扩展、原生句柄、平台消息或 KDE/GNOME 私有接口。
- Fedora KDE Wayland 和 Ubuntu GNOME Wayland 是 M6 必须完成的人工验证环境。
- Linux 路径不主动检测或排除 X11，但 M6 不针对 X11 设计、调试、测试或作出已验证兼容的承诺。
- Windows 继续使用 M5 的专用窗口框架适配层；M6 不改变 Windows 原生边界。
- macOS 继续使用原生标题栏。
- 自定义标题栏不放目标语言选择器，不提供右键菜单或自定义系统菜单。

## 范围

M6 包含：

- 在 Linux 主窗口第一次显示前应用 `Qt::FramelessWindowHint`，由 MNCE 内容区绘制标题栏
- 在 Linux 启用已有标题栏的标题、最小化、最大化或还原、关闭按钮及 Qt 标准图标
- 通过 `QWindow::startSystemMove()` 请求系统拖动，让当前 Wayland 合成器处理窗口位置、从最大化状态拖回及屏幕边缘贴靠
- 双击标题栏可拖动区域切换最大化和还原
- 通过 `QWindow::startSystemResize()` 请求四边和四角系统缩放
- 在普通窗口状态下显示对应缩放光标，在最大化状态下禁止边缘缩放及缩放光标
- 保持动态窗口标题、最小尺寸、媒体播放、关闭清理、原生对话框和现有导航行为
- Linux 窗口组件测试、主窗口 GUI 回归测试及 KDE/GNOME Wayland 人工验证

M6 不包含：

- X11 专用兼容处理、故障排查或人工验收
- 针对 KWin、GNOME Mutter 或特定 Wayland 协议扩展的专用代码
- 手写连续 `move()`、`resize()` 或窗口几何来模拟系统拖动、缩放或贴靠
- 自定义阴影、圆角、透明模糊、桌面主题匹配或标题栏视觉重设计
- 把目标语言选择器或其他业务操作移入标题栏
- 标题栏右键菜单或自定义系统菜单
- 无边框对话框；文件选择器、消息框和其他对话框继续使用原生窗口框架
- 窗口位置、尺寸或最大化状态的跨重启持久化
- Linux 应用打包、依赖部署或发行验证
- macOS 自定义标题栏

## 用户工作流

1. 用户在 KDE 或 GNOME Wayland 会话启动 MNCE，主窗口显示与 Windows 相同的 MNCE 自定义标题栏。
2. 标题栏显示当前窗口标题；进入和离开媒体详情时继续跟随现有动态标题。
3. 用户从标题栏按钮之外的区域拖动窗口，并可使用当前桌面环境的屏幕边缘贴靠。
4. 用户双击可拖动区域或单击最大化按钮，在最大化与普通状态之间切换。
5. 用户在普通状态从窗口四边或四角调整尺寸；最大化状态不显示缩放光标，也不发起缩放。
6. 用户可以最小化或关闭窗口；关闭仍经过现有 `closeEvent()` 清理流程。

## Qt 与 Linux 接口边界

- Linux 主窗口使用 `Qt::FramelessWindowHint`，但保留标准顶层窗口类型以及最小化、最大化和关闭能力标志。
- 窗口拖动仅由 `QWindow::startSystemMove()` 发起。Qt 文档将该接口作为支持原生贴靠、平铺和动画的首选方式；Wayland 不支持客户端任意设置顶层窗口位置，因此不使用 `QWidget::move()` 作为回退。
- 交互式缩放仅由 `QWindow::startSystemResize()` 发起，边缘参数只能是单边或两条相邻边。
- 最小化、最大化和还原使用 Qt 窗口操作，关闭使用 `close()`。
- 按钮图标继续使用 `QStyle::standardIcon()`；标题和最大化或还原状态继续以 Qt 窗口属性及状态事件为唯一信息源。
- `windowHandle()` 不可用，或系统移动、缩放请求返回 `false` 时，结束该次操作并保持窗口稳定，不手写几何回退。
- Linux 路径不实现 `nativeEvent()`，不新增 Linux 专用窗口框架适配层。

接口选择依据 Qt 6.11 公开文档：[QWindow](https://doc.qt.io/qt-6/qwindow.html)、[Qt Window Flags](https://doc.qt.io/qt-6/qt.html#WindowType-enum)和[Window and Dialog Widgets](https://doc.qt.io/qt-6/application-windows.html)。

## 组件职责与实现方向

- `WindowTitleBar` 继续只负责标题、按钮、可拖动区域、双击手势、可访问名称和用户操作信号。
- `FramelessWindowController` 扩展平台启用策略，在 Linux 上处理边缘命中、光标、系统移动、系统缩放和状态同步。
- `MainWindow` 只装配自定义标题栏、内容区和通用窗口控制器；Windows 适配层的安装仍由原有 `Q_OS_WIN` 路径限定。
- Linux 启用策略使用 Qt 平台宏，不根据 `XDG_CURRENT_DESKTOP`、`WAYLAND_DISPLAY` 或发行版名称建立行为分支。
- 标题栏按钮和其他可交互控件不属于拖动区域；对话框等具有独立顶层窗口的对象不得被主窗口边缘命中逻辑处理。
- 标题栏高度、缩放边距和布局间距继续使用 Qt 逻辑像素，不按 KDE、GNOME 或显示器写死物理像素。

## 实施检查点

### 检查点一：Linux 无边框启用与自动测试

包含：

- 在 Linux 启用自定义标题栏和 `Qt::FramelessWindowHint`
- 复用通用系统拖动、缩放、双击和窗口状态同步逻辑
- 扩展窗口组件与主窗口 GUI 自动测试
- Windows Debug/Release 回归构建与测试
- Fedora KDE Wayland Debug/Release 构建与自动测试

本检查点完成后汇报变更和自动验证结果，经用户确认后再进入检查点二。

### 检查点二：KDE 与 GNOME Wayland 人工验证

包含：

- 在 Fedora KDE Wayland 上检查真实窗口交互
- 在 Ubuntu GNOME Wayland 上执行 Debug/Release 构建、自动测试和真实窗口交互检查
- 在不超出 Qt 公开接口边界的前提下修正 KDE 或 GNOME 差异
- 完成 Linux 人工验收记录和 Windows 最终回归验证

如果某个目标 Wayland 合成器拒绝 Qt 系统移动或缩放请求，或无法保留所需贴靠行为，应停止对该行为的实现并向用户汇报，不自行引入桌面环境私有适配。

## 测试

M6 遵守[测试策略](testing-strategy.md)。自动测试只验证 Qt 内部可稳定观察的行为；需要 Wayland 合成器参与的真实移动、缩放、从最大化状态拖回和贴靠由人工检查覆盖，不使用依赖桌面时序的自动化断言。

自动测试至少覆盖：

- Linux 上启用自定义窗口框架并设置 `Qt::FramelessWindowHint`，Windows 仍使用专用适配层，macOS 仍保留原生标题栏
- 普通、最大化和还原状态下按钮图标与可用状态同步
- 标题栏可拖动区域发起系统移动，按钮和其他交互控件不发起移动
- 双击可拖动区域切换最大化和还原，双击按钮区域不触发切换
- 四边、四角和非边缘位置映射到正确的 `Qt::Edges`
- Linux 普通状态的边缘按下会请求系统缩放，最大化状态不会请求缩放
- 独立顶层对话框不被主窗口边缘命中逻辑处理
- Linux 主窗口显示自定义标题栏、三个窗口按钮和内容区语言选择器
- 进入媒体详情及返回媒体库时，自定义标题文字与窗口标题保持一致
- 最大化和还原后布局仍可用，关闭时仍执行播放器和后台任务的安全清理
- 现有 Windows 窗口适配和主窗口交互回归测试继续通过

KDE 与 GNOME Wayland 人工验证至少覆盖：

- 原生标题栏已隐藏，MNCE 自定义标题栏只出现一次
- 普通、最小化、最大化、还原和桌面快捷键操作正常
- 标题栏拖动、从最大化状态拖回、屏幕边缘贴靠及贴靠后恢复正常
- 四边和四角缩放、最小窗口尺寸限制，以及最大化状态不出现缩放行为
- 标题栏按钮、语言选择器和页面控件不会误触发拖动或缩放
- 标题、图标、按钮和命中区域在常用显示缩放下清晰可用
- 原生文件选择器和消息框能正常显示、聚焦并归属于主窗口

## 验收标准

1. Fedora KDE Wayland 和 Ubuntu GNOME Wayland 主窗口不显示原生标题栏，并提供与 Windows 一致的 MNCE 自定义标题栏。
2. 最小化、最大化、还原、关闭、双击切换、拖动贴靠及八方向缩放在两个必须验证环境按本文规则工作。
3. 标题栏不包含语言选择器且不提供右键菜单；语言选择器和现有业务界面保持可用。
4. Linux 实现只使用 Qt 公开接口，不使用 X11 API、Wayland 协议扩展、原生句柄、平台消息、`nativeEvent()` 或 KDE/GNOME 私有接口，不手写窗口几何模拟系统操作。
5. Windows 继续使用 M5 的专用适配层并保持已验收行为；macOS 仍保留原生标题栏。
6. X11 没有被实现代码主动排除，但不作为 M6 完成条件，也不声明已验证兼容。
7. 动态窗口标题、最小尺寸、媒体播放、关闭清理、原生对话框和现有导航没有回归。
8. 新增或调整的窗口组件及 GUI 自动测试均由 CTest 发现并通过。
9. Windows、Fedora KDE Wayland 和 Ubuntu GNOME Wayland 的 Debug 与 Release 构建及自动测试全部通过，无新增编译器警告。
10. Fedora KDE Wayland 和 Ubuntu GNOME Wayland 完成本文列出的人工窗口交互检查。
