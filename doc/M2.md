# M2：单文件媒体库基础

## 目标

建立 MNCE 的第一条实际产品链路：用户选择一个本地音频文件和目标学习语言，应用在后台计算内容哈希，将媒体信息保存到本地 SQLite 数据库，并在媒体库中展示记录。应用能够识别重复内容、标记无法访问的原文件，并允许用户重新定位缺失文件。

M2 只管理用户原文件的引用，不复制或修改音频，不播放音频，也不执行语音识别。

后续发现的未决范围或行为统一记录在 [待讨论事项](open-questions.md) 中，并在解决后同步回相应权威文档。M2 实现以用户确认后的本文档为准。

## 项目标识与数据位置

M2 使用 [平台、发行与许可证](platform-and-distribution.md) 中定义的正式项目标识、数据库文件名和默认数据位置，不在本里程碑重复定义这些值。

## 范围

M2 包含：

- 简化的媒体库首页
- 可扩充的目标语言目录，以及位于 UI 显著位置的内容空间选择
- 从任意位置添加单个音频文件
- 按媒体身份规则在后台计算文件大小和内容哈希
- SQLite 数据库初始化和 schema 版本管理
- 按内容哈希检测重复媒体
- 展示已添加的单文件媒体记录
- 检测并标记原文件缺失
- 为缺失记录重新定位文件
- 删除应用内部的媒体记录
- 对领域逻辑、数据库和文件处理建立自动测试

M2 不包含：

- 文件夹系列和目录扫描
- 音频时长读取、格式解码和内容有效性验证
- 音频播放或麦克风录音
- FFmpeg 和 whisper.cpp
- Whisper 模型管理和语音识别
- 转写、分句和学习模式
- 删除、移动或修改用户的原始音频文件
- 拖放导入、批量导入和导入队列
- 正式导航、视觉设计和发行打包

## 媒体身份

### 目标语言模型

M2 遵守 [目标语言与内容空间](target-languages.md) 中定义的通用语言目录、全局上下文、内容归属和隔离规则。本里程碑只负责将这些规则应用于单文件媒体库，不在 M2 中定义仅适用于当前 MVP 语言的特殊逻辑。

### 哈希算法

哈希算法、摘要存储形式和身份语义由 [媒体库与语音识别](media-and-transcription.md) 定义。M2 负责实现该规则，文件大小只作为辅助校验数据，不代替内容哈希。

计算规则：

- 按固定大小的数据块流式读取，不将整个文件载入内存。
- 哈希任务不得运行在 UI 线程。
- 任务期间文件无法读取或发生变化时，导入失败且不写入媒体记录。
- 哈希开始和结束时分别读取文件大小与最后修改时间；任一值发生变化都视为文件在处理期间被修改。
- 路径只用于定位文件，不参与内容身份计算。

### 重复内容

内容哈希只在目标语言范围内唯一；同一内容可以分别导入不同语言空间，但各自建立媒体记录，不共享路径、状态或后续结果。

同一内容从不同路径再次添加到相同语言空间时：

- 不创建新记录。
- 不覆盖现有记录的当前路径和目标语言。
- 界面提示该内容已经存在，并定位到现有记录。
- 如果现有记录已缺失，仍由明确的“重新定位”流程更改路径。

内容哈希相同但文件大小不同视为数据异常，拒绝自动合并并报告错误。

## 支持的文件选择

文件选择器使用 [媒体库与语音识别](media-and-transcription.md) 中列出的 MVP 计划格式，扩展名比较不区分大小写。M2 尚未集成 FFmpeg，因此只按扩展名筛选，不承诺文件内容一定能够解码；最终支持格式仍由后续 FFmpeg 集成和发行构建验证。

## 数据模型

M2 使用 schema version 1，并通过 SQLite `PRAGMA user_version` 记录版本。首次启动在事务中创建 schema；遇到高于应用支持版本的数据库时拒绝打开，并显示可操作的错误信息。

### `media_items`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PRIMARY KEY | 应用内部媒体 ID |
| `content_hash` | BLOB | NOT NULL | 完整文件的内容哈希摘要 |
| `file_size` | INTEGER | NOT NULL, CHECK >= 0 | 哈希时的文件大小 |
| `current_path` | TEXT | NOT NULL | 当前绝对文件路径 |
| `display_name` | TEXT | NOT NULL | 导入时的文件名 |
| `target_language_id` | TEXT | NOT NULL | 内置目录中的稳定语言 ID |
| `file_state` | TEXT | NOT NULL | `available` 或 `missing` |
| `transcription_state` | TEXT | NOT NULL | M2 固定为 `not_started` |
| `created_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |
| `updated_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |

表使用 `UNIQUE (target_language_id, content_hash)` 约束，同一个内容哈希在每个目标语言空间中最多出现一次。`target_language_id` 在记录创建后不可修改。数据库不使用枚举当前目录项的 `CHECK` 约束；应用在写入前通过目标语言目录验证 ID。

`transcription_state` 从 schema version 1 开始保存，尽管 M2 尚未实现转写。M2 创建的记录统一写入 `not_started`，为后续转写里程碑保留迁移兼容基础。

路径使用 Qt 规范化后的绝对路径保存，但路径大小写、文件名或位置不用于判断内容是否相同。

## 应用行为

### 启动

1. 创建应用数据目录。
2. 按平台文档定义的位置和文件名打开 SQLite 数据库。
3. 启用外键约束，并设置合理的 SQLite busy timeout。
4. 在事务中初始化或迁移 schema。
5. 读取媒体记录，在后台重新计算当前文件的完整内容哈希。
6. 路径不可访问时将记录状态更新为 `missing`；哈希不同时将原记录标记为 `missing`，并在同一语言空间为当前内容自动建立新记录。
7. 从本地设置恢复上次选择的目标语言；首次启动、设置缺失或值不在当前目录中时使用目录指定的默认语言。

数据库初始化失败时，应用不得继续显示一个看似可用的媒体库；应显示错误原因和数据库路径，并允许用户正常退出。

### 添加文件

1. 用户选择目标语言并点击“添加文件”，应用立即将当前语言 ID 固定到本次导入任务。
2. 文件选择器只显示当前允许的音频扩展名，同时验证所选路径指向可读的普通文件。
3. UI 暂时禁用重复提交，不显示哈希进度或百分比。
4. 后台任务按媒体身份规则流式计算内容哈希，同时检查文件在计算期间是否变化。
5. 应用在当前目标语言空间内查询内容哈希：
   - 不存在时，在事务中插入媒体记录。
   - 已存在时，不写入新记录并提示重复。
6. 将结果写入任务绑定的语言空间；如果用户已经切换语言，则不把该记录插入当前列表，并在完成提示中说明实际加入的语言。
7. 恢复导入操作。

M2 不提供用户主动取消哈希的操作。关闭窗口时，应用应请求后台任务停止并等待其安全结束，不得让任务继续访问已经销毁的 UI 对象。

### 缺失与重新定位

- 应用启动或刷新媒体库时在后台重新计算当前文件的完整内容哈希，不使用文件大小或修改时间跳过验证。
- 路径不存在、不可访问或不再是普通文件时，条目标记为“文件缺失”。
- 用户为缺失条目选择新文件后，应用先比较文件大小，再在后台按媒体身份规则计算完整内容哈希。
- 只有大小和内容哈希均与原记录一致时才更新 `current_path`、`display_name`、`file_state` 和 `updated_at`。
- 校验失败时保持原记录不变，并明确提示所选文件不是同一内容。

当前路径中的文件哈希与记录不同时，按媒体身份规则视为另一个文件：原记录标记为“文件缺失”，应用在同一语言空间自动新增当前文件。新记录可以与原记录使用相同的文件名和完整路径；如果当前内容哈希已经存在于该语言空间，则遵守已有的去重规则，不再重复插入。应用不显示内容变化确认或警告，文件内容完整性由用户负责。

### 删除记录

- M2 实现 [媒体库与语音识别](media-and-transcription.md) 中定义的媒体记录删除规则。
- M2 尚无转写等关联内容，持久化层在事务中移除对应的单条媒体记录。
- 删除后的同一文件可以重新导入，并获得新的内部媒体 ID。

## 用户界面

M2 将当前占位主区域替换为简化的单文件媒体库：

- 按 [页面与导航](ui-structure.md) 定义的位置和交互提供目标语言选择，选项从内置目录动态生成。
- 用户切换后立即保存当前语言，并在后续启动时恢复；无有效保存值时使用目录默认项。
- 哈希期间语言选择器保持可用；切换语言不取消任务，也不改变任务开始时固定的结果归属。
- 列表和所有媒体操作只作用于当前目标语言空间；切换语言不会改变任何已有记录。
- 媒体添加后永久归属于导入时的目标语言，M2 不提供修改语言的操作。
- 提供“添加文件”和“刷新”操作。
- 列表至少展示文件名、目标语言、文件状态和识别状态。
- M2 的识别状态统一显示为“未识别”。
- 缺失条目提供“重新定位”操作，并有清晰的视觉或文本标记。
- 媒体条目提供符合媒体管理规则的“删除记录”操作。
- 哈希期间不显示进度或忙碌提示，但暂时禁用“添加文件”以防重复提交；成功、重复和失败结果通过用户可见消息反馈。

M2 不提前建立完整的多页面导航，也不展示尚不能可靠读取的音频时长。

## 代码组织

按实际职责引入以下目录，不创建无内容的层：

```text
src/
├── domain/       # 媒体实体、语言和状态
├── persistence/  # SQLite 初始化、迁移和媒体仓储
├── services/     # 文件检查与后台哈希
└── ui/           # 媒体库界面和交互编排
```

约束如下：

- UI 不直接拼接 SQL。
- 数据库接口返回结构化结果和错误，不用控制台输出代替用户提示。
- 文件哈希服务不依赖具体界面，能够使用临时文件独立测试。
- 数据库连接遵守 Qt SQL 的线程归属规则，不跨线程共享连接。
- 使用 Qt 父对象所有权或 RAII 管理对象生命周期。

## 测试

自动测试使用临时目录、临时 SQLite 数据库和运行时生成的小文件，不依赖 `local-data/`、网络、音频设备或真实用户目录。

至少覆盖：

- 首次创建 schema 并写入正确的 `user_version`
- 重复初始化不会破坏已有数据
- 高于支持版本的数据库被拒绝
- 媒体记录的插入和读取
- 新媒体记录的转写状态为 `not_started`
- 相同内容不能重复插入同一目标语言空间
- 同内容不同路径在相同语言空间中被识别为重复
- 同一内容可以分别存在于两个不同语言空间，且两条记录互不共享
- 已知字节内容产生媒体身份文档规定的预期哈希
- 空文件和分块读取的哈希行为
- 不可读、消失或处理期间变化的文件返回结构化错误
- 缺失状态检测不删除已有记录
- 刷新时通过完整内容哈希识别路径相同但内容已经不同的文件，将原记录标记为缺失并自动新增当前内容
- 内容变化产生的新旧记录允许具有相同的文件名和完整路径，且不显示确认或警告
- 重新定位仅接受大小和哈希均匹配的文件
- 删除操作遵守媒体管理文档定义的记录与原文件边界，删除后允许重新导入
- 目录提供的语言 ID 能往返持久化，不在目录中的语言 ID 被拒绝
- 目标语言首次使用目录默认项，切换后能够在下次启动时恢复，失效设置值回退到目录默认项
- 哈希期间切换目标语言不会中断任务，结果只写入任务开始时绑定的语言空间
- 使用增加了第三种测试语言的目录时，不修改 schema 或 UI 逻辑即可创建并切换其内容空间
- 主窗口能够展示空媒体库和至少一条媒体记录

本地手动测试音频放在仓库根目录的 `local-data/audio/`，整个 `local-data/` 目录不纳入版本控制。

## 验收标准

M2 在满足以下全部条件后完成：

1. 全新用户数据目录下启动应用会自动创建有效的 schema version 1 数据库。
2. 用户可以选择 MVP 内置目录中的任一目标语言并添加一个受支持扩展名的本地文件。
3. 文件哈希在后台执行，期间界面保持响应。
4. 媒体记录在应用重启后仍然存在并正确显示。
5. 从其他路径向同一目标语言空间添加相同内容不会产生重复记录。
6. 不同目标语言只显示各自的媒体，同一内容可分别导入且记录互不共享。
7. 原文件移动或删除后，媒体记录被标记为缺失且内部数据保留。
8. 原路径存在但内容哈希变化时，原记录标记为缺失，并在同一语言空间自动新增当前内容且不提示用户。
9. 用户能够用内容相同的文件重新定位缺失记录，错误文件会被拒绝。
10. 媒体记录删除行为符合媒体管理文档中的规则。
11. 数据库和文件错误会显示用户可操作的信息，不只写入控制台。
12. Debug 和 Release 均无新增编译器警告并能成功构建。
13. CTest 能发现所有测试，且测试全部通过。
14. 自动测试不访问网络、音频设备、真实用户目录或 `local-data/`。
15. 数据库、测试音频和其他本地运行数据不会出现在 Git 待提交列表中。
