# 分句服务

## 总体流程

Whisper 原始文本是不可修改的 Ground Truth。分句服务只负责确定学习单元边界，不拥有纠正识别文本的权限。

处理优先级：

1. 完成本地 Whisper 识别。
2. 若用户已配置在线 AI，则请求在线分句。
3. 校验 AI 没有改写原文。
4. 校验通过后采用 AI 分句结果。
5. 请求失败、返回非法或文本被修改时，自动使用本地规则分句。

用户未配置 API Key 时，本地分句自动启用，无需手动选择。

## 在线 AI

MVP 默认提供 DeepSeek 预设，同时允许用户配置 OpenAI-compatible 服务。

DeepSeek 预设由应用提供服务地址和默认模型字段，用户提供自己的 API Key。自定义服务至少需要：

- API Base URL
- API Key
- 模型名称

MVP 以兼容 Chat Completions 风格的请求和响应为边界，不承诺兼容所有声称“OpenAI-compatible”的扩展行为。

## 数据与隐私

- 在线分句只发送识别文本和分句所需的结构信息，不上传原始音频。
- 首次使用前必须明确提示文本将发送给第三方服务。
- API Key 不得明文存入 SQLite、日志或崩溃报告。
- API Key 应保存到操作系统安全凭据存储中。
- 网络错误信息必须隐藏或脱敏密钥。

应用没有自有后端，也不代理用户请求。第三方服务的费用、配额、隐私政策和可用性由用户与服务商之间的关系决定。

## 结果约束

- AI 应返回原文中的边界位置或稳定编号，而不是任意重写后的段落。
- 应用必须验证重新拼接后的文本与 Whisper Ground Truth 一致。
- AI 可以添加必要标点，但标点与原始字符的保存和比较规则仍需在协议设计时明确。
- 分句结果需要映射回 Whisper 的时间轴。
- Whisper 提供稳定的段级时间戳，但更细粒度的 token 时间戳属于实验性能力，因此句内切分的时间精度需要实测。

## 本地分句

本地分句作为自动回退方案，使用标点、停顿和最大长度等简单规则。它的目标是保证应用始终可用，而不是达到在线 AI 的自然语言分句质量。

本地算法的具体规则和英日差异待后续设计。
