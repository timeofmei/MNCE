# 音频播放

> 状态：已确认。本文规则作为 M4 及后续学习模式共用播放能力的实现基线。

## 定位

音频播放是媒体详情页和后续学习模式共用的本地能力。播放器只读取用户原始音频，不复制、移动、修改文件，也不改变媒体的内容身份。

M4 先建立整段音频播放能力。按句播放、句间静音、循环、录音及学习模式专属控制留给对应里程碑。

## 播放入口与生命周期

- 单文件列表和系列详情中的媒体名称均可进入统一媒体详情页。
- 打开详情只加载媒体信息，不自动开始播放，也不触发内容哈希。
- 应用同时只维护一个播放器和一个当前媒体；切换媒体、离开详情或关闭窗口时停止当前播放。
- 再次打开媒体从头开始，不跨页面或应用重启保存播放位置。
- 当前文件缺失时保留详情，但禁用播放和进度操作，并提供既有重新定位入口。
- 播放路径不可读、格式无效或解码失败时显示用户可见错误；播放失败不自动修改内容哈希或建立新媒体记录。

## 基础控制

- 提供播放、暂停和进度跳转，不提供用户主动停止控制。
- 同时显示当前位置和总时长，统一使用 `mm:ss`；超过一小时后使用 `h:mm:ss`。
- 媒体不可跳转时禁用进度拖动。
- 提供 `0.5×`、`0.75×`、`1.0×`、`1.25×`、`1.5×` 和 `2.0×` 倍速，默认 `1.0×`。
- 应用不提供音量控制；用户通过操作系统或音频输出设备调节音量。
- 倍速属于应用级偏好，在所有目标语言空间中共用并跨重启保存；未知或不在支持档位中的值回退到 `1.0×`。
- 切换媒体时沿用当前倍速。
- M4 使用系统默认音频输出设备，不提供输出设备选择器和均衡器。

## 时长

- `media_items` 和 `series_media_items` 增加可空的 `duration_ms`，单位为毫秒；未知时为 `NULL`，已知值必须大于等于 0。
- 打开媒体详情后异步加载播放源；播放器报告有效时长后，在数据库连接所属线程保存该值。
- M4 不为整个媒体库预先批量探测时长，避免打开应用或列表时产生大量文件访问。
- 列表中已知时长按统一格式显示，未知时显示 `—`；播放源成功加载后同步更新详情和列表。
- 时长是文件派生信息，不参与媒体身份、去重或重新定位判断。

## 技术边界

- M4 使用 Qt 6.11.2 的 `QMediaPlayer` 和 `QAudioOutput`，通过 Qt Multimedia 默认媒体后端播放，不直接调用 FFmpeg API。
- 软硬件解码路径由 Qt Multimedia 默认后端自动选择；应用不强制指定硬件设备，也不依赖 Qt Multimedia 的私有环境变量改变生产配置。
- Qt Multimedia 播放对象在应用/UI 线程中创建和使用；媒体加载与播放本身采用其异步接口，不阻塞 UI。
- UI 通过可替换的播放边界观察状态、位置、时长、可跳转状态和结构化错误，使自动测试不依赖真实声卡或系统解码器。
- M4 不自行维护解码线程、PCM 缓冲区或播放队列。后续 whisper.cpp 所需 PCM 解码仍由独立转写边界负责。
- 发行阶段必须验证 Qt Multimedia 实际使用的媒体后端、运行库部署和许可证；不得假设开发机可播放就代表所有目标平台均可播放。

## 错误与状态

播放器至少区分：未加载、加载中、已停止、播放中、已暂停和错误。用户切换媒体后，旧媒体的迟到回调不得覆盖当前详情状态。

加载或播放错误必须包含可执行的用户提示，例如文件缺失、无权限、格式不支持或无法解码。底层错误可用于诊断，但不向用户展示无法理解的裸错误码。

## 已确认决策

1. 使用 Qt Multimedia 默认后端，M4 不直接集成 FFmpeg API；软硬件解码路径由 Qt 自动选择。
2. 时长采用“打开详情后懒加载并写入 schema version 3”，不在启动或显示列表时批量探测。
3. 使用本文列出的倍速档位，并将倍速作为跨语言的应用级偏好。
4. 应用不提供音量控制。
5. 打开详情不自动播放，切换媒体或离开详情后不保留播放位置。
