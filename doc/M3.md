# M3：文件夹系列

> 状态：已确认。检查点一已实现，等待用户验收；检查点二尚未开始。

## 目标

在 M2 单文件媒体库的基础上增加文件夹系列。用户可以把一个本地文件夹关联为系列，按稳定顺序查看其中的直属音频，并通过刷新和重新定位处理文件增减或文件夹移动。

M3 继续只引用用户原文件，不复制、移动、修改或删除音频。文件内容身份、目标语言归属和跨语言隔离分别遵守[媒体库与语音识别](media-and-transcription.md)及[目标语言与内容空间](target-languages.md)中的通用规则。

## 范围

M3 包含：

- 媒体库中的“文件夹系列”标签
- 选择一个文件夹并创建系列
- 创建时指定系列名称，并永久绑定当前目标语言
- 扫描文件夹直属的受支持音频，不递归子文件夹
- 单文件列表和系列列表按名称或添加时间正序、倒序排列
- 系列内部按文件名自然顺序正序或倒序排列
- 打开系列时自动扫描，以及用户主动刷新
- 刷新时加入新文件并标记消失的文件
- 系列文件夹移动后的重新定位
- 删除系列及其独立拥有的应用内部数据
- 从 M2 schema version 1 安全迁移并保留已有单文件记录
- 文件夹扫描、系列持久化、刷新与界面工作流的自动测试

M3 不包含：

- 音频时长读取、格式解码或内容有效性验证
- 音频播放和麦克风录音
- FFmpeg、whisper.cpp、模型管理和语音识别
- 转写、分句和学习模式
- 递归扫描、文件夹监控或后台自动监控
- 拖放导入、任意批量文件导入和导入队列
- 将音频复制进应用数据目录
- 正式视觉设计和发行打包

## 已确定的产品行为

### 目标语言

- 用户从当前目标语言空间创建系列，系列和扫描产生的内容永久绑定该语言 ID。
- 系列名称去除首尾空白后不能为空；保存去除首尾空白后的名称。
- 同一目标语言空间内，系列名称按 Unicode 大小写折叠后不得重复；不同目标语言空间允许同名系列。
- 切换全局目标语言只改变当前显示空间，不迁移或修改系列。
- 扫描任务创建时固定语言 ID；任务期间切换语言不会改变结果归属。
- 数据模型和界面不能假设目标语言目录只有英语和日语。

### 数据归属与隔离

- 每个系列独立拥有自己的媒体记录、识别结果和后续数据。
- 系列扫描发现的内容即使已经存在于同一语言的单文件库或另一个系列，也在当前系列建立独立记录，不复用已有记录或结果。
- 相同内容可以同时存在于单文件库和多个系列中；删除、刷新、缺失检测、重新定位和后续处理均互不影响。
- 每个容器内部按内容哈希去重：同一系列中的相同内容只建立一条媒体记录，不重复转写和存储后续数据。
- 内容哈希用于当前容器内的身份判断、去重和重新定位，但不能作为跨容器合并数据的依据。
- 删除系列时一并删除该系列独立拥有的全部媒体记录、识别结果和后续数据，不保留不可访问的孤立记录；该操作不影响用户原始音频、单文件库或其他系列。

### 文件夹扫描

- 只扫描所选文件夹的直属普通文件，不进入子文件夹。
- 文件扩展名范围沿用[媒体库与语音识别](media-and-transcription.md#媒体范围)中的计划格式，扩展名比较不区分大小写。
- M3 尚未集成 FFmpeg，因此扩展名符合只表示进入候选列表，不保证文件内容能够解码。
- 文件内容哈希必须在后台流式计算，不得阻塞 UI 线程。
- 文件在读取期间消失、不可读或发生变化时，按结构化错误处理，不写入不完整记录。
- 扫描候选文件按文件名自然正序依次处理；遇到同一系列内内容哈希相同的文件时，只保留自然顺序靠前的文件。

### 刷新与缺失

- 创建系列后执行首次扫描。
- 打开系列时自动扫描，同时提供手动刷新操作。
- 刷新发现的新音频加入系列。
- 已记录但无法在系列文件夹中找到的音频保留内部数据并标记为缺失。
- 路径仍存在但内容已经变化时，沿用媒体身份规则：原内容标记为缺失，当前内容作为新内容处理。
- 已记录文件消失但同一系列文件夹中仍有另一个内容哈希相同的文件时，刷新自动将原记录更新到仍存在的路径，不标记为缺失。

### 排序

- 单文件列表只允许按文件名称或添加时间排序，两种字段均支持正序和倒序。
- 系列列表只允许按系列名称或添加时间排序，两种字段均支持正序和倒序。
- 系列内部只允许按文件名自然排序，并支持正序和倒序。
- 单文件列表和系列列表首次使用时默认按添加时间倒序；系列内部首次使用时默认按文件名自然正序。
- 三类列表分别记忆用户最后选择的排序字段和方向，跨应用重启保存，并作为应用级界面偏好在所有目标语言空间中共用。
- 所有上述列表均不允许拖动或通过上移、下移等操作手动调整位置。
- 刷新发现新文件后，按照当前系列内部的文件名排序方向重新计算整个列表，不保存独立位置值。
- 文件名自然排序必须独立于当前系统区域设置，确保同一组文件得到确定结果。

### 文件夹重新定位

- 原系列文件夹不可访问时，系列保留并显示缺失状态。
- 用户可以选择新的文件夹位置进行重新定位。
- 应用扫描候选文件夹，并通过完整内容哈希恢复已有内容关联，不能只依赖文件名、相对路径、文件大小或修改时间。
- 重新定位不得改变系列的目标语言和当前排序设置。

## 用户界面

- 媒体库按照[页面与导航](ui-structure.md)提供“单文件”和“文件夹系列”两个标签。
- 系列列表只展示当前目标语言空间中的系列。
- 提供“添加文件夹”入口；创建时选择文件夹并输入系列名称。
- 系列至少展示名称、文件夹状态和条目数量。
- 系列名称为空或与当前目标语言中的已有系列重名时，创建失败并显示明确提示。
- 打开系列后展示按文件名排序的条目列表、缺失状态、刷新和重新定位操作。
- 单文件列表和系列列表提供名称、添加时间、正序和倒序选项；系列内部只提供文件名、正序和倒序选项。
- 提供删除系列操作；执行前必须二次确认，确认内容和影响范围遵守[媒体库与语音识别](media-and-transcription.md#文件夹系列)中的规则。
- 扫描、哈希或数据库失败必须通过用户可见信息反馈，不能只写入控制台。
- 长时间扫描期间界面保持响应，并避免对同一系列重复发起冲突任务。

## 持久化与迁移

M3 将数据库升级为 schema version 2。现有 `media_items` 表继续只表示单文件库，不改变其字段、ID 或唯一约束。系列及其媒体使用独立表，不把 M2 记录迁移或复制到系列中。

### `media_series`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PRIMARY KEY | 系列内部稳定 ID |
| `name` | TEXT | NOT NULL | 去除首尾空白后的显示名称 |
| `normalized_name` | TEXT | NOT NULL | `name` 的 Unicode 大小写折叠结果，用于同语言重名检查 |
| `target_language_id` | TEXT | NOT NULL | 创建时绑定的目标语言 ID |
| `current_directory` | TEXT | NOT NULL | Qt 规范化后的当前绝对文件夹路径 |
| `directory_state` | TEXT | NOT NULL | `available` 或 `missing` |
| `created_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |
| `updated_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |

表使用 `UNIQUE (target_language_id, normalized_name)` 约束同一语言空间内的系列名称。`normalized_name` 由应用使用 `QString::trimmed()` 后再调用 `QString::toCaseFolded()` 生成，数据库不能用依赖系统区域设置的比较规则代替。`current_directory` 不作为系列身份或唯一键；路径相同的系列仍是互不共享数据的独立容器。

### `series_media_items`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PRIMARY KEY | 系列媒体内部稳定 ID |
| `series_id` | INTEGER | NOT NULL, FOREIGN KEY | 所属 `media_series.id`，删除系列时级联删除 |
| `content_hash` | BLOB | NOT NULL | 完整文件的 SHA-256 摘要 |
| `file_size` | INTEGER | NOT NULL, CHECK >= 0 | 哈希时的文件大小 |
| `current_path` | TEXT | NOT NULL | Qt 规范化后的当前绝对文件路径 |
| `display_name` | TEXT | NOT NULL | 当前文件名 |
| `file_state` | TEXT | NOT NULL | `available` 或 `missing` |
| `transcription_state` | TEXT | NOT NULL | M3 固定为 `not_started` |
| `created_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |
| `updated_at` | TEXT | NOT NULL | UTC ISO 8601 时间 |

表使用 `UNIQUE (series_id, content_hash)` 实现系列内部去重。它不对 `content_hash` 单独建立全局唯一约束，也不引用 `media_items`，因此实现单文件库、系列与系列之间的数据隔离。系列媒体的目标语言通过所属系列获得，不额外保存一份可能失配的语言 ID。

### 迁移规则

1. 打开数据库后读取 `PRAGMA user_version`，高于 2 时拒绝打开。
2. version 1 升级在一个事务中创建 `media_series`、`series_media_items` 及查询所需索引，不修改 `media_items` 中的现有数据。
3. 启用外键约束，`series_media_items.series_id` 使用 `ON DELETE CASCADE`。
4. 全部 schema 操作成功后设置 `PRAGMA user_version = 2` 并提交；任一步失败时回滚。
5. 全新数据库直接得到完整的 version 2 schema；重复初始化不修改已有数据。

至少为系列按目标语言和添加时间查询、系列媒体按 `series_id` 查询建立索引。自然名称排序由应用层的确定性比较器完成，不依赖 SQLite 或操作系统当前区域设置。

## 排序偏好

排序字段和方向属于应用级界面偏好，保存在现有本地设置中，不写入媒体或系列表：

- 单文件列表：字段默认为添加时间，方向默认为倒序。
- 系列列表：字段默认为添加时间，方向默认为倒序。
- 系列内部：字段固定为文件名，方向默认为自然正序。

三类偏好分别保存。读取到未知字段或方向时回退到对应默认值；切换目标语言时复用同一组偏好。按名称排序时使用确定性的自然比较：数字片段按数值比较，非数字片段使用 Unicode 大小写折叠结果比较；仍相同时以原始名称和稳定 ID 依次打破平局。按添加时间排序时以 `created_at` 为主键、稳定 ID 为次键，确保结果稳定。

## 扫描与刷新流程

1. 创建扫描任务时固定系列 ID、目标语言 ID 和文件夹路径，之后不重新读取当前 UI 语言。
2. 枚举文件夹直属的候选普通文件，并按确定性的文件名自然正序排列；自然比较结果相同时以规范化绝对路径打破平局。子文件夹和不支持的扩展名不进入任务。
3. 在后台依次计算候选文件的大小和完整哈希，并沿用 M2 对读取期间文件变化的检查。
4. 按内容哈希合并当前系列内的候选；相同哈希和大小只保留自然顺序靠前者，相同哈希但大小不同视为数据异常。
5. 生成刷新计划：已有哈希更新路径、名称和可用状态；新哈希插入新记录；未在完整扫描结果中出现的已有哈希标记为缺失。
6. 在数据库连接所属线程中用一个事务应用完整刷新计划。提交成功后再更新界面；失败时回滚并保留刷新前状态。

如果文件夹整体不存在或不可访问，只把系列标记为 `missing`，保留其媒体记录及各自原状态。候选枚举或任一文件哈希失败时，不应用部分刷新计划，并向用户报告失败文件和原因。已记录路径消失但扫描到相同内容的其他路径时，按自然正序选择候选并更新原记录，不产生缺失记录。

系列重新定位先对用户选择的新文件夹执行同样的完整扫描和哈希；成功后在一个事务中更新系列路径、文件夹状态和媒体刷新计划。扫描失败时保持原系列不变。重新定位不通过文件夹名称、相对路径或文件大小单独判定身份。

## 代码与职责边界

- `domain/` 增加系列、系列媒体、文件夹状态和排序选项等不依赖 UI 或 SQL 的类型。
- `persistence/` 负责 version 2 迁移、系列及系列媒体查询，以及创建、刷新、重新定位和删除事务；UI 不拼接 SQL。
- `services/` 负责目录枚举、确定性自然排序、后台哈希和刷新计划生成；文件系统扫描逻辑不依赖具体界面。
- `ui/` 负责编排异步任务、当前语言视图、排序控件和用户反馈，不在 UI 线程进行目录哈希。
- 文件夹选择、系列名称输入、删除确认和消息显示使用可替换的界面边界，使 GUI 端到端测试能够驱动窗口而不操作原生对话框。
- 数据库连接继续遵守 Qt SQL 线程归属规则；后台任务只返回值对象和刷新计划，不持有或使用 UI 线程的数据库连接。
- 关闭窗口时请求扫描任务停止并等待安全结束，不允许异步回调访问已经销毁的 UI 对象。

## 实施检查点

M3 保持为一个里程碑，但分为两个需要分别汇报和验收的实施检查点。检查点一完成后先向用户说明代码、迁移和测试结果，经确认后再进入检查点二，不一次性完成全部实现。

### 检查点一：数据与服务层

包含：

- 增加系列、系列媒体、文件夹状态和排序选项等领域类型
- 实现确定性自然排序比较器
- 实现 schema version 2 迁移
- 实现系列及系列媒体仓储
- 实现目录枚举、后台哈希和扫描结果归并
- 实现创建、刷新、缺失检测、重新定位和删除所需的服务逻辑
- 建立领域、迁移、持久化和服务层自动测试

本检查点不接入正式系列界面，不改变用户当前可操作的 M2 单文件工作流，因此不要求新增 GUI 端到端测试或人工界面检查。

检查点一验收条件：

1. version 1 数据库可以升级到 version 2，原有单文件记录不变，迁移失败能够回滚。
2. 单文件库、不同系列之间的数据相互独立，同一系列内部按内容哈希去重。
3. 扫描、刷新、缺失检测、重新定位和删除逻辑可以通过无 UI 的服务接口完整执行。
4. 文件枚举、哈希和刷新计划生成不依赖 UI 线程或具体窗口。
5. 新增单元和组件测试由 CTest 发现并全部通过。
6. Debug 和 Release 构建无新增编译器警告。

### 检查点二：界面与完整工作流

包含：

- 接入媒体库“单文件”和“文件夹系列”标签
- 实现系列列表、创建系列和系列详情界面
- 实现刷新、重新定位和删除确认交互
- 为单文件列表、系列列表和系列内部列表接入规定的排序选项
- 保存并恢复三类应用级排序偏好
- 使用可替换界面边界隔离文件夹选择、名称输入、确认框和消息框
- 增加系列工作流的 GUI 端到端测试
- 完成 Windows 人工界面验证

检查点二验收条件：

1. 用户能够从主窗口完成创建、查看、刷新、重新定位和删除系列的完整流程。
2. 语言切换、排序选择和异步任务结果在界面上符合本文规则。
3. 删除系列必须经过二次确认，且不会影响用户原文件或其他容器。
4. 本文规定的 GUI 端到端工作流均由 CTest 发现并通过。
5. 完整 Debug、Release 和 CTest 验证通过。
6. Windows 人工检查确认常用窗口尺寸和显示缩放下没有文字截断、控件重叠或异常焦点状态。

## 测试

M3 遵守[测试策略](testing-strategy.md)中的分层自动测试和人工界面验证要求。测试使用临时目录、临时数据库和运行时生成的小文件，不访问真实用户目录、网络、音频设备或 `local-data/`。

至少覆盖：

- schema version 1 升级后保留已有单文件媒体，重复初始化不破坏数据
- 创建、读取和按目标语言隔离系列
- 系列名称的空白处理、空名称拒绝、同语言重名拒绝和跨语言同名允许
- 相同内容在单文件库和多个系列中分别建立记录，任一容器中的操作不改变其他容器
- 相同内容在同一系列内只建立一条记录，并确定性地保留文件名自然顺序靠前的文件
- 已保留文件消失时，刷新能够自动改用同一系列内仍存在的相同内容文件
- 删除系列会删除其全部内部数据，但保留原始音频以及单文件库和其他系列的数据
- 删除系列必须先显示二次确认，取消确认时不改变任何数据
- 只扫描直属文件，忽略子文件夹和不支持的扩展名
- 单文件列表和系列列表的名称、添加时间、正序及倒序排序
- 系列内部文件名自然排序的正序、倒序及确定性，包括数字序号
- 三类列表的默认排序，以及排序偏好跨重启和目标语言切换后的恢复
- 刷新加入新文件并标记消失文件
- 原路径内容变化时正确保留原内容并处理新内容
- 系列文件夹缺失和通过内容哈希重新定位
- 扫描期间切换目标语言不改变结果归属
- 增加第三种测试语言不需要修改 schema 或通用 UI 逻辑
- 扫描失败、数据库失败和任务冲突返回结构化错误

GUI 端到端测试至少覆盖：

- 通过窗口创建系列，完成扫描后按自然顺序显示直属音频
- 刷新系列后，新文件出现且消失文件显示为缺失
- 切换各列表允许的排序字段和方向后，界面按对应顺序显示
- 原文件夹移动后，通过界面重新定位并恢复系列内容

## 草案验收标准

1. 用户可以在当前目标语言空间中选择文件夹、命名并创建系列。
2. 系列名称去除首尾空白后不能为空，同一目标语言内不允许大小写不同的重名系列，不同目标语言允许同名。
3. 首次扫描只加入文件夹直属的受支持音频，界面在后台处理期间保持响应。
4. 单文件列表和系列列表只能按名称或添加时间正序、倒序排列；系列内部只能按文件名自然顺序正序或倒序排列，所有列表均不提供手动排序。
5. 打开或手动刷新系列会加入新文件，并将消失或内容已变化的原条目标记为缺失。
6. 文件夹移动后，用户能够选择新位置，并通过内容哈希恢复原有关联和排序设置。
7. 系列及其内容严格遵守目标语言归属和隔离规则。
8. 相同内容可以独立存在于单文件库和多个系列，任何容器中的操作都不影响其他容器的数据。
9. 同一系列内的相同内容只显示一个条目，并保留文件名自然顺序靠前的文件；该文件消失但仍有相同内容文件时，刷新自动恢复路径。
10. schema version 1 数据库能够安全升级，已有 M2 数据不丢失；迁移失败能够完整回滚。
11. 删除系列前必须二次确认；确认后事务化删除其全部应用内部数据，但保留用户原始音频，且不影响单文件库和其他系列。
12. 用户文件不会被应用复制、移动、修改或删除。
13. 相关单元测试、组件测试和 GUI 端到端测试均由 CTest 发现并通过。
14. Debug 和 Release 均无新增编译器警告并成功构建。
15. 在 Windows 基线环境中完成人工界面检查，确认常用窗口尺寸和显示缩放下无文字截断、控件重叠或状态显示问题。
