# M1：可编译的桌面应用骨架

## 目标

建立 MNCE 的第一个可执行工程，使项目从产品文档阶段进入可持续开发阶段。完成后，开发者应能在 Windows 上使用固定的 Qt、MSVC、CMake 和 Ninja 配置完成构建、启动应用并运行自动测试。

M1 只验证工程结构和基础技术链路，不实现实际媒体管理、语音识别或学习功能。

## 环境基线

- Windows 11 x86-64
- Visual Studio Community 2026 提供的 MSVC x64 工具链
- Windows SDK 10.0.26100
- Qt 6.11.2 `msvc2022_64`
- CMake 3.30.5
- Ninja 1.12.1

Qt 需要以下模块：

- Core
- Widgets
- Network
- Sql
- Multimedia
- Concurrent
- Test，仅测试目标使用

CMake 配置最低要求 Qt 6.11.2。Windows 开发与发行验证仍使用上述 Qt 6.11.2 kit。

## 交付内容

### 工程文件

- 根目录 `CMakeLists.txt`
- `CMakePresets.json`
- `.gitignore`
- `src/CMakeLists.txt`
- `tests/CMakeLists.txt`

CMake 工程应满足：

- 使用 C++20，并禁用编译器扩展。
- 使用 target-scoped include、compile option 和 link 配置。
- 启用 Qt 的 AUTOMOC、AUTOUIC 和 AUTORCC。
- Windows 构建启用合理的 MSVC 警告和 UTF-8 源码处理。
- 通过 `BUILD_TESTING` 控制测试目标。
- Debug 和 Release 使用独立构建目录。
- 不在仓库中写死开发者账户目录或其他私人路径。

### 建议目录结构

```text
MNCE/
├── CMakeLists.txt
├── CMakePresets.json
├── AGENTS.md
├── doc/
├── src/
│   ├── CMakeLists.txt
│   ├── main.cpp
│   └── ui/
│       ├── main-window.cpp
│       └── main-window.h
└── tests/
    ├── CMakeLists.txt
    └── application-smoke-test.cpp
```

随着后续功能增加，再按实际职责引入 `domain`、`persistence` 和 `services` 等目录；M1 不提前创建空的架构层。

### 最小应用

生成一个名为 `mnce` 的 GUI 可执行目标：

- 创建 `QApplication`。
- 创建并显示 `MainWindow`。
- 窗口标题包含 `MNCE`。
- 主区域显示明确的开发阶段占位内容。
- 关闭主窗口后应用正常退出。

M1 不确定正式反向域名、应用 ID、包名和数据库名。不得为了完成骨架而将临时值记录为正式产品标识。

### 基础测试

使用 Qt Test 和 CTest 建立至少一个冒烟测试目标，验证：

- 能构造 `QApplication` 和 `MainWindow`。
- 主窗口具备预期标题或其他稳定的基础属性。
- Qt 运行时版本不低于 6.11.2。
- `QSQLITE` 驱动可用，并能打开内存数据库。

测试不得访问网络、真实音频设备、Whisper 模型或用户目录。

### 开发部署

为 Windows 动态 Qt 开发构建提供明确的运行方式。应用至少应能通过以下一种方式启动：

- 在配置正确的开发终端中直接运行；或
- 将所需 Qt DLL 和插件部署到独立运行目录后启动。

如果 M1 集成 `windeployqt`，它应作为显式部署步骤，不应在每次普通编译时无条件执行。

## 构建预设

至少提供以下预设：

- `windows-msvc-debug`
- `windows-msvc-release`

预设使用 Ninja 和 MSVC x64。Qt 路径应通过 `QT_ROOT` 环境变量或等价的非私人配置传入，例如：

```powershell
$env:QT_ROOT = 'C:\Qt\6.11.2\msvc2022_64'
```

构建应在 Visual Studio Developer PowerShell 中进行，或者由 IDE 初始化等价的 MSVC 环境。标准验证流程为：

```powershell
cmake --preset windows-msvc-debug
cmake --build --preset windows-msvc-debug
ctest --preset windows-msvc-debug
```

Release 预设执行相同的配置、构建和测试流程。

## Git 忽略项

`.gitignore` 至少排除：

- CMake 和 Ninja 构建目录
- CMake 用户预设
- Visual Studio、Visual Studio Code 和 Qt Creator 的本机状态
- 编译产物、部署目录和安装包
- 测试临时文件及日志
- SQLite 用户数据库及其 WAL/SHM 文件
- Whisper 模型和下载临时文件

不要忽略项目共享的 `CMakePresets.json`、源代码、测试资源或许可证文件。

## 明确不包含

M1 不包含：

- 媒体库页面和正式导航结构
- 持久化数据库文件或业务表结构
- 音频播放和麦克风录音
- FFmpeg 集成
- whisper.cpp 和 Whisper 模型
- 模型下载
- DeepSeek 或自定义分句 API
- 三种学习模式
- 静态 Qt 构建
- MSI、ZIP 或其他正式发行包
- 代码签名、SBOM 和正式第三方许可证页面
- CI 服务配置

这些内容必须在工程骨架稳定后分阶段加入。

## 验收标准

M1 在满足以下全部条件后完成：

1. 全新检出的仓库不需要修改受版本控制的文件即可配置工程。
2. Windows Debug 和 Release 预设均能成功配置并编译。
3. 编译过程没有新增的编译器警告。
4. 应用能启动、显示主窗口并正常退出。
5. CTest 能发现测试，且所有测试通过。
6. 冒烟测试确认 Qt 运行时版本不低于 6.11.2，且 `QSQLITE` 可用。
7. 构建输出、IDE 状态和运行时临时文件不会出现在 Git 待提交列表中。
8. README 或等价开发说明包含可直接执行的配置、构建、测试和启动命令。

## 完成后的下一步

M1 完成后进入媒体库基础阶段：确定正式项目标识和数据库名称，设计 SQLite schema，实现单个音频文件的添加、内容哈希、重复检测、缺失标记与重新定位。
